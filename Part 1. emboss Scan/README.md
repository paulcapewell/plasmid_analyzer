# P1 Use Emboss Profit to Identify Hits

These scripts:
 - open the plasmid database you are searching and create a cached version for ease of acces
 - use EMBOSS profit to search for any hits on any of the Xer frequency matrices and record them (+ location where)
 - use EMBOSS profil to search the hits from ^ to confirm if they also contain ArgR somewhere, using those frequency matrices



 ## Wokflow

First, update the email used in script 01_open_plasmid_database.py line 17 to your own

Then run the scripts in the following order:

1. `101_open_plasmid_database.py`
2. `102_xer_matrix_scan.py`
3. `103_argR_matrix_scan.py`

Each script uses output files generated by the preceding step.

## Requirements
 - python 3.9 or newer
 - Biopython
 - EMBOSS (this script was developed using EMBOSS:6.6.0.0)
 - Internet access to fetch GenBank records from NCBI when running the first script
 - FOR and REV ArgR frequency matrices
 - FOR and REV XerC/D frequency matrices for 6, 7, and 8bp crossover region lengths
 - A gzipped FASTA database named `bacterial_plasmids_curated.fa.gz` in:
    `input_folder`/`full_plasmid_sequence_database`/
   
    Either use this one: 
    https://figshare.com/articles/dataset/Complete_plasmids_ARG_carriage_study/19438994?file=34537640

     or select an alternative database for ther analysis, and...
          either 1) name it `bacterial_plasmids_curated.fa.gz` 
          or 2) ajust the name in line 14 of the script 01_open_plasmid_database.py. 
          **in this case, you must ensure you use the same database later on in the plasmid analyzer for `P2 Analyze Sequence and Metadata of Hits`**

# Run the first script, 01_open_plasmid_database.py

Run from the project root so the relative input

```powershell
python 101_open_plasmid_database.py
```

## What it does
mostly copies the logic from Paul's original plasmid_analyzer pyxerscipt.py to open and cache the file, and it generates a receipt you can use later to verify the original plasmid database used (by using SHA256)

## output files
both located in output_folder / cached_plasmid_database

sequence_database_cache.bin.gz is the main output file, which is the cached database

receipt.txt includes some summary details that can help clarify the origin of the sequence database, such as SHA256.
     i.e., if sha256 of the input and cached databases you are examining match this receipt, you know you have the corresponding files. If any tiny change has happened to either file, these sha256 values won't match the receipt here.



# Run the second script, 02_xer_frequency_marix_serach.py

Run from the project root so the relative input

```powershell
python 102_xer_matrix_scan.py
```

## What it does
uses EMBOSS profit to search for hits with every xer frequency matrix

makes a list of hits with their coordinates for every xer frequency matrix

it also makes a receipt.txt file with these sha256 values for each input file so you can locate any changes amde to input files.

## output files
`xerCD hits before ArgR` / .txt files
      files for every frequency matrix, with a list of hits and positions and percentage matches

`file_identity_and_integrity` / `receipt.txt` 
     file with these sha256 values for each input file so you can locate any changes amde to input files.



# Run the third script, 03_argR_frequency_matrix_search.py

Run from the project root so the relative input

```powershell
python 103_argR_matrix_scan.py
```

## What it does
uses EMBOSS profit to further analyze the XerCD hits, based on if they are ArgR hits as well, by applying the ArgR frequency matrix

## output files
For every `HITS XerCD... .txt` file the script analyzes, it produces 3 output files in `output folder`
     in `ArgR Hits` folder: a list of every ArgR hit for the plasmids in side HITS XerCD is made, with coordinates and percent match

     in "xerCD hits after ArgR" is a copy of `HITS XerCD... .txt` with a new name after removing any plasmid where no ArgR was found

     in "XerCD hits failed ArgR scan" is a list of every `HITS XerCD... .txt` plasmid where no ArgR was found


it also makes a receipt.txt file in `file_identity_and_integrity` folderwith these sha256 values for each input file so you can locate any changes amde to input files, for the same reason as in the second script
